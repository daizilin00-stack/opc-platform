## 一、项目背景

中新数据港 OPC 数字平台（OpenClaw Partner Center）依托中新（重庆）互联网数据专线，为创业者提供 AI 数字员工 SaaS 服务。平台需要**合规、稳定、低延迟**的跨境网络连接，将国内用户请求通过中新数据港跨境专线传输至新加坡 AWS 节点，再访问海外大模型 API（OpenAI / Claude）。

**核心场景：** 国内用户实时调用海外 AI 大模型（流式对话，"打字机效果"），需要低延迟、高可靠性的跨境网络。

## 三、带宽需求计算

### 3.1 业务场景分析

| 场景 | 并发数 | 单次请求大小 | 单次响应大小 | 流式输出 |
|------|--------|-------------|-------------|----------|
| 大模型对话（文本） | 100 | 2-5 KB | 1-20 KB | 是（SSE） |
| 大模型对话（代码） | 50 | 5-10 KB | 5-50 KB | 是（SSE） |
| 文件上传（知识库） | 20 | 1-10 MB | 200 KB | 否 |
| 后台管理/普通API | 50 | 1-5 KB | 5-50 KB | 否 |

### 3.2 带宽计算

**假设：** 峰值并发 100 用户同时流式调用海外大模型

| 方向 | 流量特征 | 计算 | 峰值带宽 |
|------|----------|------|----------|
| **上行**（国内→海外） | 用户请求 + 系统开销 | 100用户 × 5 KB × 1次/秒 | **5 Mbps** |
| **下行**（海外→国内） | 流式响应（主流量） | 100用户 × 500 tokens/s × 4字节 × 8位 | **16 Mbps** |
| **突发**（文件上传） | 20用户 × 5 MB / 30秒 | 并发上传 | **27 Mbps** |
| **合计** | 上行 + 下行 + 突发余量 | 按 1:1 冗余设计 | **≥ 100 Mbps** |

**结论：基础带宽需求 ≥ 100 Mbps，建议首期配置 100-200 Mbps，支持平滑升级至 1 Gbps。**

## 四、延迟（Latency）要求

### 4.1 端到端延迟拆解

| 路径段 | 目标延迟 | 说明 |
|--------|----------|------|
| 用户 → 平台后端 | < 50 ms | 国内 CDN / 就近部署 |
| 平台后端 → 中新数据港专线入口 | < 20 ms | 同区域或就近接入 |
| 中新数据港专线 → 新加坡 | < 100 ms | **核心要求：跨境段** |
| 新加坡 → AWS ap-southeast-1 | < 10 ms | 本地同城 |
| AWS → 海外模型 API | < 50 ms | 互联网段 |
| **端到端总计** | **< 250 ms** | 用户感知延迟 |

### 4.2 流式交互要求

- **首字延迟（Time to First Token）：** < 500 ms（用户发送请求到收到第一个响应字）
- **流式间隔：** 连续流式输出，每 50-100 ms 一个 token
- ** jitter（抖动）：** < 50 ms（保证流式输出平滑，不卡顿）

## 五、可靠性与 SLA 要求

| 指标 | 要求 | 说明 |
|------|------|------|
| **可用性** | ≥ 99.95% | 月度可用性，年停机 < 4.38小时 |
| **丢包率** | < 0.1% | 跨境段 |
| **误码率** | < 10^-9 | 专线物理层 |
| **故障恢复** | < 5分钟 | 自动切换至备用路径 |
| **MTTR** | < 4小时 | 平均修复时间 |
| **MTBF** | > 8760小时 | 平均故障间隔（1年） |

## 六、安全与合规要求

### 6.1 合规资质（硬性要求）

| 资质 | 要求 | 说明 |
|------|------|------|
| **跨境通信许可** | 必须持有 | 工信部颁发的国际数据通信业务经营许可证 |
| **中新政府背书** | 优先 | 中新（重庆）战略性互联互通示范项目合作方 |
| **数据跨境合规** | 必须满足 | 符合《数据出境安全评估办法》及相关法规 |
| **等保三级** | 必须满足 | 网络侧至少满足等保 2.0 三级要求 |

### 6.2 技术要求

| 要求 | 规格 |
|------|------|
| **加密传输** | 全链路 TLS 1.3，支持 IPSec VPN 或 MACsec |
| **DDoS 防护** | ≥ 10 Gbps 清洗能力 |
| **访问控制** | 基于源 IP / 目的 IP / 端口的精细化 ACL |
| **流量审计** | 支持 NetFlow/sFlow，日志保留 ≥ 180 天 |
| **物理隔离** | 专线与其他租户逻辑隔离，可选物理隔离（价格另议） |

## 七、与 AWS 的对接要求

### 7.1 对接方式

| 方式 | 要求 | 说明 |
|------|------|------|
| **AWS Direct Connect** | **首选** | 在 AWS 新加坡区域（ap-southeast-1）建立 DX 连接 |
| **Transit Gateway** | 必须支持 | 便于多 VPC / 多账户的网络拓扑管理 |
| **BGP 路由** | 必须支持 | eBGP 邻居，支持路由通告和过滤 |
| **VLAN 划分** | 必须支持 | 支持 802.1Q VLAN，公网/私网流量隔离 |
| **IPv4 + IPv6** | 必须支持 | 双栈，未来-proof |
| **带宽粒度** | 50 Mbps / 100 Mbps / 200 Mbps / 500 Mbps / 1 Gbps | 灵活选择 |

## 十二、附录：关键问题清单（谈判用）

### 12.1 必问问题

1. **是否持有工信部国际数据通信业务经营许可证？**（硬性合规）
2. **是否有中新（重庆）项目合作背景？**（政策优势）
3. **重庆到新加坡的实际延迟是多少？**（要求实测）
4. **是否支持 AWS Direct Connect 在新加坡的接入？**（技术兼容性）
5. **是否支持 BGP 和 Transit Gateway？**（网络架构）
6. **故障切换时间是多少？**（可靠性）
7. **月度 SLA 报告包含哪些指标？**（运维透明度）
8. **带宽升级流程和时间？**（弹性）
9. **是否支持双路由冗余？**（高可用）
10. **技术支持是否 7×24 中文？**（服务）
