## 一、合作模式选项

基于双方资源禀赋，推荐以下三种模式（可组合）：

### 模式 A：B2B 采购代理（最务实）

**本质**：OPC 是 LingAPI 的大客户，享受阶梯折扣

```
LingAPI ←── 大额采购 + 预存 ──→ OPC 平台
                │
                ↓
           用户（不知道 LingAPI 存在）
```

**适用场景**：快速启动，最小摩擦

| 条款 | 建议 |
|------|------|
| 合作身份 | OPC 作为平台级客户，非经销商 |
| 结算方式 | 月结（平台上线后）或预存（测试期） |
| 价格折扣 | **2.4 折（朋友价，已谈定）** |
| 锁价条款 | 年度框架协议，锁定 2.4 折不变 |
| 最小起订 | 无（利用朋友关系） |
| 合同期限 | 年度框架协议 |
| 退出机制 | 提前30天通知，未消费余额退还 |

**优点**：简单直接，无额外义务
**缺点**：OPC 仍需自行承担品牌和运营

---

### 模式 B：白标/OEM 合作（最理想）

**本质**：LingAPI 提供"裸 API"，OPC 包装成自有品牌

```
用户 → OPC 品牌 API → OPC 网关 → LingAPI 裸 API
         （用户看不到 LingAPI）
```

**关键要求**：

| 项目 | 具体需求 |
|------|---------|
| **响应脱敏** | 移除 LingAPI 特征响应头（如 `x-new-api-version`） |
| **错误重写** | 错误码统一为 OPC 格式，不暴露上游信息 |
| **域名支持** | 支持 OPC 自有域名调用（CNAME 或反向代理） |
| **账单分离** | LingAPI 只给 OPC 总账单，不触碰终端用户 |
| **品牌隔离** | 任何场景不暴露 LingAPI 品牌给用户 |

**适用场景**：长期合作，品牌独立性要求高

**谈判筹码**：
> "我们平台用户是 B2B 企业客户，如果他们知道你们，可能会绕过我们直接找你们。白标保护的是双方利益。"

**加价比代理模式高 5-10%**（白标服务有额外成本）

---

### 模式 C：联合运营/收入分成（最深入）

**本质**：双方共同投入，共享收益

```
LingAPI 出：技术 + 模型渠道
OPC 出：客户资源 + 品牌 + 运营

收入按约定比例分成
```

**分成方案建议**：

| 层级 | OPC 分成 | LingAPI 分成 | 适用 |
|------|---------|-------------|------|
| 基础 | 60% | 40% | 通过 OPC 渠道获客的用户 |
| 进阶 | 70% | 30% | 月流水 > ¥50 万时 |
| 独家 | 75% | 25% | OPC 承诺排他性（不接入其他同类渠道） |

**适用场景**：双方高度互信，长期战略绑定

**风险**：需要法律协议保障，财务对账复杂

---

### 模式 D：混合模式（推荐）

**组合**：B2B 代理（保底）+ 白标（主力）+ 联合运营（增量）

```
┌────────────────────────────────────────┐
│           混合合作架构                    │
├────────────────────────────────────────┤
│  基础层：B2B 采购协议                    │
│  - 年度锁价，阶梯折扣                     │
│  - 月结，最小摩擦                         │
├────────────────────────────────────────┤
│  服务层：白标 API 服务                   │
│  - 自有域名调用                          │
│  - 响应脱敏，品牌隔离                     │
├────────────────────────────────────────┤
│  增值层：联合运营（可选）                 │
│  - 新客推荐返佣                          │
│  - 大客户联合 BD                         │
│  - 收入分成                              │
└────────────────────────────────────────┘
```

**推荐以此模式作为谈判目标**

## 二、谈判要点清单

### 第一轮：试探摸底（朋友闲聊，非正式）

**目标**：了解对方底线，建立合作意向

**话题**：
1. "你们现在主要客户是什么类型？"
   - 了解他们是否缺大客户
2. "平台级客户有什么特殊政策？"
   - 试探 B2B 折扣空间
3. "能不能支持自有域名调用？"
   - 试探白标可能性
4. "你们现在最大的风险是什么？"
   - 了解他们对合规、封控的态度

**产出**：非正式合作意向

---

### 第二轮：框架协议（正式商务谈判）

**目标**：锁定核心条款

**必备条款**：

#### 1. 价格与折扣

```
┌──────────────┬────────────┬────────────┐
│   月消耗量    │  折扣比例   │  实际倍率   │
├──────────────┼────────────┼────────────┤
│  < ¥5 万     │  无折扣     │  公开价     │
│  ¥5-20 万    │   9 折     │  ×0.9      │
│  ¥20-50 万   │   8 折     │  ×0.8      │
│  > ¥50 万    │  另议      │  战略价     │
└──────────────┴────────────┴────────────┘
```

**谈判技巧**：
- 先报预期用量（放大 20%）："我们预计首月 ¥30 万，三个月内到 ¥80 万"
- 要求阶梯价，而非固定价："先按 8 折锁一年，用量上去后再谈"
- 锚定效应：先提"你们竞争对手给我们 7.5 折"（即使没这回事）

#### 2. 结算与账期

| 选项 | 对 OPC | 对 LingAPI |
|------|--------|-----------|
| 预存制 | 资金占用 | 现金流好 |
| 月结制 | 现金流好 | 有坏账风险 |
| 周结制 | 折中 | 折中 |

**建议谈判**：
- 测试期：预存 ¥1-2 万（2.4 折后成本极低，风险可控）
- 平台上线后：月结（现金流友好）
- 核心目标：**年度框架协议锁定 2.4 折**，不因用量变化而调整

#### 3. SLA 保障

**必须写入协议**：

```
服务可用性：≥ 99.5%（月度统计）
故障响应：P0 级故障 ≤ 15 分钟响应
                P1 级故障 ≤ 1 小时响应
                P2 级故障 ≤ 4 小时响应

不可用补偿：按不可用时间比例返还当月额度
            或：延长服务期

封控预警：如预知封控/墙，提前 24 小时通知
         如未提前通知，按 P0 故障处理
```

#### 4. 数据与隐私

```
数据使用：LingAPI 不得存储 OPC 终端用户的对话内容
          仅保留脱敏后的计费统计数据（token 数、模型名）

安全认证：LingAPI 需通过 SOC2 Type II 或 ISO 27001 认证
          或提供等效安全证明

审计权利：OPC 有权每年一次审计 LingAPI 的数据处理流程
          提前 30 天预约，LingAPI 配合提供材料
```

#### 5. 品牌与合规

```
白标条款：LingAPI 同意在 OPC 用户的请求链路中不暴露品牌
          包括但不限于：响应头、错误信息、状态页、文档

反向担保：OPC 承诺不对外声称模型由 LingAPI 提供
          宣传口径为"通过 CSDP-WAN 海外专线"

合规责任：LingAPI 对其服务可用性负责
          OPC 对终端用户的网络合规负责
          双方各自承担法律责任
```

---

### 第三轮：技术对接（落地执行）

**目标**：确定技术细节，签署正式合同

**技术对接清单**：

| 项目 | 说明 | 责任方 |
|------|------|--------|
| 域名 CNAME | 支持 `api.opc-platform.com` 指向 LingAPI | LingAPI |
| SSL 证书 | 支持 OPC 自有证书上传 | 协商 |
| 响应头清洗 | 移除 `x-new-api-version` 等特征头 | LingAPI |
| 错误码映射 | 将 LingAPI 错误码映射为 OPC 标准码 | LingAPI 或 OPC |
| 日志格式 | 统一为 OPC 格式，包含用户级追踪 ID | 协商 |
| 计费精度 | 实时计费查询接口（每小时） | LingAPI |
| 用量告警 | 用量达阈值时主动通知 OPC | LingAPI |

## 三、谈判策略与话术

### 开场三板斧

**第一斧：身份锚定**

> "我们不是散户，是中新数据港——中新（重庆）战略性互联网数据专线的运营方。陆海产业园 OPC 数字平台是我们旗下的 AI 数字员工服务平台。"

**目的**：让对方知道你是"大客户"，不是个人开发者。

---

**第二斧：价值展示**

> "我们的平台目前服务 XX 名创业者，预计 3 个月内日活突破 XXXX。每个用户背后都是企业级调用量。我们不是在买 API，是在找一个能一起长大的合作伙伴。"

**目的**：从"交易"升级为"战略合作"。

---

**第三斧：痛点共鸣**

> "我知道你们现在最大的挑战是什么——散户多、利润薄、合规风险大。跟我们合作，你能获得稳定的 B 端流水，而且我们帮你承担终端用户的合规和品牌风险。"

**目的**：让对方觉得合作对他也有利。

---

### 应对常见推脱

**对方说："我们主要是做 C 端，B 端没有特殊政策。"**

> 回应："C 端用户人均月消费多少？我们一个平台客户顶你 1000 个 C 端用户。而且 B 端客户流失率低，续费稳定。你们现在 C 端获客成本越来越高，跟我们合作等于零成本获客。"

---

**对方说："白标做不了，技术上不支持。"**

> 回应："OneAPI 架构本身支持多租户，只需要配置一个自定义域名和响应头过滤。这不是技术上做不到，是愿不愿意做。我们愿意为此付溢价，加 10% 怎么样？"

---

**对方说："价格已经是最低了，没有空间。"**

> 回应："公开价确实没空间。但我们是年度框架协议，不是按量随时买。我们可以预付，可以承诺最小用量，可以签排他。这些条件值多少折扣？"

---

**对方说："SLA 99.5% 做不到，我们最多 99%。"**

> 回应："99% 意味着每月停机 7 小时。我们的企业客户不能接受。这样吧，先写 99%，但每低 0.1% 返还 5% 当月费用。这样你们有动力做到 99.5%。"

## 四、合同关键条款模板

### 保密条款

```
双方对本合作的内容、价格、技术细节负有保密义务。
未经对方书面同意，不得向第三方披露。
例外：OPC 有权向监管机构披露合作事实（不披露价格细节）。
```

### 竞业/排他条款（可选）

```
如 OPC 承诺在同类服务中优先使用 LingAPI（非排他），
LingAPI 给予额外 5% 折扣。

如 OPC 承诺在特定客户群体中不引入 LingAPI 竞争对手，
LingAPI 给予额外 10% 折扣。
```

### 终止条款

```
任何一方提前 30 天书面通知，可终止合作。

终止时：
- 未消费余额：LingAPI 在 15 个工作日内退还
- 在途请求：继续处理直至完成
- 数据迁移：LingAPI 配合导出计费明细
```

### 不可抗力

```
因网络封控、政策变化、上游厂商终止服务等不可抗力
导致服务不可用，双方互不承担违约责任。

但受影响方需及时通知对方，并尽力提供替代方案。
```
