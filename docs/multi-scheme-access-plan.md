## 一、客户自带专线接入方案

### 场景定义

客户已通过其他渠道（或历史购买）拥有跨境网络能力，只需要 OPC 平台的**模型调用服务**。

### 技术架构

```
┌─────────────────────────────────────────────┐
│              客户侧                          │
│  ┌──────────┐    ┌──────────────────────┐  │
│  │ 客户业务  │───→│ 自有专线/VPN/其他    │──┼──→ 海外出口
│  │ 系统     │    │ 网络出口             │  │
│  └──────────┘    └──────────────────────┘  │
│       │                                     │
│       │ API Key + Base URL                  │
│       ↓                                     │
│  ┌──────────────────────────────────────┐  │
│  │ OPC 平台 API 网关 (api.opc-platform.com)│  │
│  │ - 认证鉴权                            │  │
│  │ - 计费扣款                            │  │
│  │ - 路由分发                            │  │
│  └──────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
                    │
                    ↓
┌─────────────────────────────────────────────┐
│           OPC 平台侧                         │
│  ┌──────────────────────────────────────┐  │
│  │ 智能路由网关                          │  │
│  │ ┌────────┐ ┌────────┐ ┌──────────┐ │  │
│  │ │LingAPI │ │302.AI  │ │新加坡直连│ │  │
│  │ │(主力)  │ │(备份1) │ │(备份2)   │ │  │
│  │ └────────┘ └────────┘ └──────────┘ │  │
│  └──────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

### 接入方式对比

| 接入方式 | 适用客户 | 技术复杂度 | 计费方式 |
|---------|---------|-----------|---------|
| **API Key 直接调用** | 有开发能力的企业 | 低 | 按量计费 |
| **OPC SDK 集成** | 需要快速接入的开发者 | 中 | 按量计费 |
| **硅基员工托管** | 无技术能力的创业者 | 低 | 订阅制 |
| **私有网关部署** | 大型集团客户 | 高 | 年框合同 |

### 自带专线客户的特殊处理

**1. 网络层：客户自理**
- 客户负责自己的跨境网络连通
- OPC 不介入网络，只做服务可用性保障

**2. 服务层：OPC 统一提供**
```javascript
// 客户调用示例
const response = await fetch('https://api.opc-platform.com/v1/chat/completions', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer opc-xxxxxxxxxxxxx',  // OPC 平台 API Key
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    model: 'gpt-4.5',  // 客户不需要知道上游是 LingAPI 还是其他
    messages: [{ role: 'user', content: 'Hello' }]
  })
});
```

**3. 计费层：平台统一结算**
- 所有调用走 OPC 计费系统
- 客户只看到 OPC 账单，不感知上游渠道
- 支持预付费（套餐包）+ 后付费（按量）双模式

**4. 合规层：责任划分**
- 客户自带专线的合规性由客户自行负责
- OPC 提供的是"模型调用服务"，不是"跨境网络服务"
- 用户协议明确：客户需确保自身网络访问符合当地法规

## 二、LingAPI 合作谈判策略

### 谈判筹码

| 优势 | 说明 |
|------|------|
| **中新数据港品牌** | 有实体公司、有专线资质、有政府背景（陆海产业园） |
| **稳定大客户** | 不是散户，是平台级 B2B2C 采购 |
| **长期合作** | 不是一锤子买卖，是持续稳定的用量 |
| **私人关系** | 可以谈更灵活的条件 |

### 谈判目标

#### 目标 1：B2B 代理价格

**当前 LingAPI 公开价格**：
- GPT-5.5：输入 2.5x，输出 6x（以 500K tokens 为基准单位）
- 1 单位 = 50万 tokens，售价 ¥6.8

**谈判方向**：
- 月消耗量 > ¥5万：申请 **9 折**
- 月消耗量 > ¥20万：申请 **8 折**
- 预存 ¥10万：申请 **85 折 + 账期**（月结而非预存）

#### 目标 2：API 白标服务（隐藏品牌）

**需求**：
- 请求响应中不暴露 LingAPI 特征
- 错误信息可以自定义
- 状态页可以嵌入到 OPC 控制台

**谈判话术**：
> "我们不是拿你的服务去卖，而是作为上游渠道之一。我们的客户只认识中新数据港，不认识 LingAPI。如果客户知道了你们，可能会绕过我们直接找你们。所以白标对我们双方都有利。"

#### 目标 3：SLA 保障

**要求**：
- 月度可用性 > 99.5%
- 故障响应时间 < 15 分钟
- 封控/墙时提前 24 小时通知
- 不可用时间按比例返还额度

#### 目标 4：数据安全承诺

**要求**：
- 不存储用户对话内容（仅用于计费统计）
- 支持 SOC2 / ISO27001 合规证明
- 接受年度安全审计

### 谈判话术框架

```
开场：
"我们是中新数据港，中新（重庆）战略性互联网数据专线的运营方，
旗下 OPC 平台是一个 AI 数字员工即服务平台。目前平台有 XX 名注册用户，
预计月模型调用量 XX 万 tokens。"

价值：
"我们不是散户，我们是平台级客户。我们的用户会通过我们的平台调用你们的服务，
这意味着你们获得的是稳定的、可预期的、持续增长的收入。"

需求：
"基于我们的用量规模和长期合作意愿，我们希望谈三件事：
1. 阶梯代理价；2. API 白标；3. SLA 保障。"

交换：
"作为交换，我们可以：
- 首月预存 ¥XX 万
- 签署年度框架协议
- 在合适的场景下推荐你们的品牌（非强制白标场景）"
```

## 三、企业专线硬件部署准备

### CPE 设备清单

| 设备 | 型号/规格 | 数量 | 单价(估) | 用途 |
|------|----------|------|---------|------|
| **SD-WAN CPE** | 企业级，支持 IPSec/SSL VPN | 按客户数 | ¥2000-5000/台 | 客户端接入 |
| **汇聚路由器** | 支持 BGP/OSPF | 2 台（主备） | ¥15000/台 | 数据中心汇聚 |
| **防火墙** | 下一代防火墙 | 2 台（主备） | ¥20000/台 | 安全策略 |
| **交换机** | 千兆/万兆 | 若干 | ¥5000/台 | 接入交换 |
| **光模块** | SFP+ 10G | 若干 | ¥500/个 | 光纤连接 |

### 部署流程

```
1. 客户下单 → 确认专线带宽、接入点
        ↓
2. 设备采购 → CPE + 配件
        ↓
3. 预配置 → 远程写入配置模板（SN 绑定）
        ↓
4. 快递寄送 → CPE 寄到客户地址
        ↓
5. 远程安装指导 → 视频/文档 + 客服支持
        ↓
6. 上联激活 → 数据中心端配置 BGP 邻居
        ↓
7. 测试验收 → 测速 + 延迟 + 丢包率
        ↓
8. 交付使用 → 客户使用 OPC 平台服务
```

### 客户侧安装要求

| 项目 | 要求 |
|------|------|
| **电源** | 220V 稳定供电，UPS 备用 |
| **上联** | 客户侧至少一条可用互联网线路 |
| **机位** | 标准机架或桌面放置（CPE 尺寸类似路由器） |
| **技术人员** | 能接网线、能进路由器后台 |
| **公网 IP** | 如有固定 IP，提前提供给我们 |

### 远程运维能力

**必须实现的功能**：
- CPE 状态监控（在线/离线/流量/CPU/内存）
- 远程配置下发（策略更新、路由调整）
- 远程重启/恢复出厂
- 告警通知（微信/邮件/SMS）

## 四、过渡阶段执行方案

| 周次 | 行动 | 产出 |
|------|------|------|
| W1 | 开通 302.AI、NanoGPT 账户 | 2 个备用渠道 |

| W2 | 部署多上游网关 | 代码上线 |
| W2 | 测试 LingAPI 稳定性 | 7 天可用率报告 |
| W3 | 灰度放量：50% 用户走 LingAPI | 监控数据 |

| W4-W8 | 持续监控 + 优化 | 月度运营报告 |
