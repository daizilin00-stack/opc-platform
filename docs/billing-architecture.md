## 核心理念

**"云资源分离计费"：基础设施费 + 用量费，用多少付多少**

## 二、Token 用量计费（按量计费模式）

### 核心理念

> **"用多少算多少，不用不花钱"**

用户调用AI模型时，平台按实际消耗的Token数量计费。

### 计费模型

| 层级 | 说明 | 计费方式 |
|------|------|----------|
| **接入层** | 用户调用平台API | 平台记录Token消耗 |
| **调度层** | 平台选择最优模型 | 国内模型/海外模型不同价 |
| **采购层** | 平台统一买海外API | 批发价，分摊给多个用户 |

### Token 定价（参考）

| 模型 | 输入Token | 输出Token | 备注 |
|------|-----------|-----------|------|
| **GPT-4o** | ¥0.017/千Token | ¥0.052/千Token | 海外模型，能力强，含15%平台服务费 |
| **GPT-4o-mini** | ¥0.0017/千Token | ¥0.0052/千Token | 海外模型，性价比，含15%平台服务费 |
| **Claude 3.5** | ¥0.021/千Token | ¥0.063/千Token | 海外模型，长文本强，含15%平台服务费 |
| **Kimi** | ¥0.003/千Token | ¥0.006/千Token | 国内模型，中文强，无加价（成本已低） |
| **通义千问** | ¥0.002/千Token | ¥0.005/千Token | 国内模型，通用，无加价（成本已低） |

> **平台加价**：在模型成本上加 **15%** 作为平台服务费（董事长确认）


### 计费特点

- **预充值实时扣费**：用户先充值到钱包，每次API调用实时扣费（董事长确认）
- **透明**：每次API调用返回消耗Token数和费用
- **套餐包**：可预购Token包（如¥500买100万Token，享8折）
- **余额预警**：余额不足时提醒，欠费暂停海外模型（国内模型可继续）

## 三、AI 数字员工计费（增值订阅）

### 与Token的关系

| 费用类型 | 说明 | 关系 |
|----------|------|------|

| **Token用量费** | 员工实际工作的"材料费" | 按实际调用Token计费 |

| 类比 | 说明 |

## 七、数据库表设计

```sql
-- 用户钱包
CREATE TABLE wallets (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    balance DECIMAL(12,2) DEFAULT 0,
    frozen DECIMAL(12,2) DEFAULT 0,
    currency VARCHAR(3) DEFAULT 'CNY',
    updated_at TIMESTAMP
);

-- 计费项目（专线/Token/AI员工/存储）
CREATE TABLE billing_items (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    item_type VARCHAR(50), -- 'dedicated_line' | 'token' | 'agent' | 'storage'
    item_name VARCHAR(100),
    amount DECIMAL(12,2),
    quantity DECIMAL(12,4), -- Token数量/存储GB/带宽M
    unit VARCHAR(20), -- 'CNY' | 'token' | 'GB' | 'Mbps'
    period_start TIMESTAMP,
    period_end TIMESTAMP,
    status VARCHAR(20), -- 'pending' | 'paid' | 'overdue'
    created_at TIMESTAMP
);

-- Token调用记录（实时记录）
CREATE TABLE token_usage (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    agent_type VARCHAR(50),
    model_name VARCHAR(50), -- 'gpt-4o' | 'claude-3.5' | 'kimi'
    prompt_tokens INTEGER,
    completion_tokens INTEGER,
    total_tokens INTEGER,
    cost_cny DECIMAL(12,4),
    created_at TIMESTAMP
);

-- 专线服务订阅
CREATE TABLE line_subscriptions (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    line_type VARCHAR(50), -- 'csdp-wan' | 'network-accel' | 'sdwan'
    bandwidth INTEGER, -- Mbps
    monthly_fee DECIMAL(12,2),
    start_date DATE,
    end_date DATE,
    status VARCHAR(20),
    created_at TIMESTAMP
);
```

## 八、业务流程

### 用户开通服务

```
1. 注册重庆公司
2. 签署平台服务合同
3. 充值钱包（预充值，如¥1,000起）
4. 购买专线服务（选择带宽/周期）→ 扣固定费
5. 雇佣AI员工（选择角色/数量）→ 扣订阅费
6. 开始使用 → Token实时计费（每次调用从钱包扣款）
7. 余额不足时：提醒充值 → 海外模型暂停，国内模型可用
```

### 欠费处理

```
钱包余额不足
    │
    ▼
┌─────────────┐
│ 第一阶段：预警 │  余额<¥500时短信/邮件提醒
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 第二阶段：限制 │  余额<0时，海外模型禁用，仅国内模型可用
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 第三阶段：暂停 │  欠费7天，暂停所有AI服务，专线保留
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 第四阶段：终止 │  欠费30天，终止服务，数据保留90天后删除
└─────────────┘
```

## 九、关键决策点（已确认）

### 1. Token计费模式 ✅ 已确认

**董事长确认：预充值实时扣费**

- 用户充值到钱包（如¥1,000）
- 每次API调用，实时显示"本次消耗XXX Token，¥X.XX"
- 余额不足时暂停海外模型，国内模型继续（国内模型成本低，可容忍小额欠费）
- 现金流健康，用户体验好

### 2. 专线与Token的绑定关系 ✅ 已确认

**董事长确认：B+C模式**

| 选项 | 说明 | 状态 |
|------|------|------|
| **A. 必须买专线才能用Token** | 强制捆绑，收入稳定但门槛高 | ❌ 不采用 |
| **B. Token可单独购买** | 灵活，用户可先体验AI再决定买专线 | ✅ 采用 |
| **C. 买专线送Token额度** | 促销手段，如买专线送¥500 Token | ✅ 采用 |

**执行策略：**
- 基础：Token可单独购买，降低体验门槛
- 促销：买专线首年送Token额度（如买10M专线送¥500 Token额度），鼓励升级
- 用户可先买Token体验AI，满意后再买专线获得额外赠送

### 3. Token加价率 ✅ 已确认

**董事长确认：15%**

- 海外模型（GPT-4o/Claude）：成本价 + 15% = 平台售价
- 国内模型（Kimi/通义）：不加价（成本已低，作为引流）
- 用户感知：Token套餐折扣，不直接暴露加价率

### 4. 计费透明度

| 选项 | 说明 |
|------|------|
| **A. 实时显示** | 每次调用后显示消耗Token和费用 |
| **B. 每日汇总** | 每天推送昨日用量账单 |
| **C. 仅月底账单** | 月底统一出账单 |

**建议：A+B（实时+日汇总）**
- API返回头中插入 `X-Token-Cost: 0.035`
- 控制台实时展示当日累计
- 每晚推送用量日报
